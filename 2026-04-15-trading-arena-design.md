## Problem Statement
The current product already supports strategy storage, analysis, and backtesting, but it is broad. The sharper product is a learning sandbox where multiple strategies face the same historical market conditions and explain why they bought, sold, or held at each decision point.

This is for one primary user: you. The value is not automated profit. The value is building trading intuition by comparing different decision systems under a fair, controlled replay.

## What Makes This Cool
Two or three strategies see the exact same candle sequence and still make different decisions. You can pause on any step, inspect the state, and read a clear explanation of why one strategy entered while another stayed flat. The "whoa" moment is seeing market interpretation diverge in real time instead of just comparing final PnL.

## Constraints
- This should be useful as a learning tool before it is useful as a trading tool.
- The first version should reuse the existing React, Express, SQLite, and backtester stack.
- The first version should avoid live trading and avoid pretending an AI can predict markets.
- The first version should stay narrow: one symbol, one timeframe, two or three built-in strategies, historical replay, and explanation-first UX.
- Results must be fair: same candles, same fees, same starting balance, same execution assumptions.

## Premises
1. The right first product is not an autonomous trader. It is a comparison arena for strategies on identical historical data.
2. Explanations are more valuable than headline returns for the first version.
3. Historical replay is the fastest path to a genuinely useful tool because it removes live execution complexity and makes outcomes reproducible.
4. A small set of deterministic built-in strategies is better than open-ended strategy generation for the first version.
5. The existing `Backtest` and `Strategy Lab` surfaces should be converged instead of expanded into more parallel product areas.

## Approaches Considered
### Approach A: Full AI Trading Agent
Build a single LLM-backed agent that reads market state and emits trades, then let the user compete against it.

This is the wrong first move. It creates fake intelligence risk, weak reproducibility, prompt-fragile behavior, and poor learning value because most disagreement would come from opaque reasoning rather than inspectable rules.

### Approach B: Strategy Arena Replay Lab
Build a deterministic replay environment where multiple strategies process the same candle stream, produce trade decisions, and attach structured explanations to each action.

This is narrower, fairer, easier to verify, and better for learning. It also fits the codebase that already has a backtester, strategy registry, analyzer, and charting UI.

## Recommended Approach
Build `Strategy Arena Replay Lab` as a focused mode that sits between the current `Backtest` and `Strategy Lab` concepts.

The core loop:
1. Choose a symbol, timeframe, and date range.
2. Choose two or three strategies.
3. Run the shared replay.
4. Step through candles or play them forward.
5. At each decision event, inspect:
   - current candle and indicator state
   - each strategy's position state
   - each strategy's action: buy, sell, hold, reduce, reverse
   - a structured explanation of why that action happened
6. Review the final comparison summary:
   - equity curve
   - drawdown
   - trade count
   - win rate
   - key divergence moments

The explanation system should not be free-form by default. Start with deterministic explanation payloads produced by each strategy evaluation step, for example:

```js
{
  action: "buy",
  confidence: 0.74,
  reasons: [
    "fast EMA crossed above slow EMA",
    "RSI recovered above 50",
    "no open position"
  ],
  blockers: [
    "volume below recent median"
  ],
  state: {
    emaFast: 42150.2,
    emaSlow: 42080.7,
    rsi: 53.8
  }
}
```

That gives you a truthful baseline. If an LLM layer is added later, it should translate this structured state into better prose, not invent the reasons.

## Open Questions
- Should the first replay mode be single-symbol only, likely `BTCUSDT 1h`, to reduce UX and performance complexity?
- Which first three strategy archetypes best teach contrast: trend-following, mean-reversion, and breakout is the current best guess.
- Should the user be able to place their own manual trades during replay in v1, or should that wait until the arena comparison loop is stable?
- Should strategy explanations be generated per candle, or only on action and near-action events to reduce noise?

## Success Criteria
- You can run the same historical window against at least two strategies and get reproducible results.
- You can replay the run candle by candle and inspect each strategy's decision state.
- You can identify at least three moments where strategies diverged and understand why.
- The product makes it easy to learn something concrete, such as "trend-followers entered late but rode longer" or "mean-reversion kept fading moves that never reverted."
- The first version is simple enough that you would actually use it repeatedly to study setups.

## Distribution Plan
This should ship as part of the existing web app.

- Frontend delivery: existing Vite React app
- Backend delivery: existing Express server and SQLite persistence
- Deployment: existing local workflow and current deployment pipeline
- No new package distribution is needed for v1

If this becomes valuable, a later distribution expansion could include saved replay sessions and sharable comparison URLs.

## Next Steps
1. Refactor the backtester output model so each strategy can emit per-step decision events and explanation payloads, not just aggregate results.
2. Define a small shared strategy interface for arena-compatible strategies:
   - `init`
   - `onCandle`
   - `getIndicators`
   - `explainDecision`
3. Add two or three built-in strategies chosen for contrast, not performance:
   - EMA trend follower
   - RSI mean reversion
   - Donchian breakout or momentum breakout
4. Create a backend arena route that runs selected strategies on the same candle stream and returns:
   - summary metrics
   - synchronized decision timeline
   - equity curves
   - divergence markers
5. Replace or extend the current backtest UI with an arena view:
   - strategy picker
   - replay controls
   - shared chart
   - side-by-side decision panels
   - final comparison summary
6. Add a "Key Moments" view that jumps straight to candles where strategies disagreed.
7. Only after the deterministic version is solid, consider an optional AI narration layer that rewrites structured reasons into cleaner teaching language.

## What I noticed about how you think

- The part you cared about most was "having an AI explain why it bought/sold while..." which points to learning and interpretability over blind automation.
- When offered several wedges, you accepted the narrower path quickly, which suggests you value a tool you can use soon over an ambitious but vague system.
